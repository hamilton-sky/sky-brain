1 · The brain model

Three kinds of memory, one board in the middle

Agents and people never message each other outside the board: an urgent need becomes a question item on it. They read and write the shared brain, and a nightly Steward, the Consolidator, decides what becomes long-term memory.

3 · Data model

Postgres holds the truth; md is how it reads

The tables grow from what already runs in production (entries, goals, tasks, task events, memberships).

Why one Postgres, no graph database

A person makes 10k–100k items over years. A recursive query over the indexed links table answers 1–3 hops in milliseconds at that size. Item, links, embedding and event commit in one transaction, under one permission model and one backup. If deep graph queries are ever needed, the Apache AGE extension adds Cypher inside Postgres (check Nanogres first). Revisit only for 4+ hop queries or graph algorithms on large shared brains.

Generic tables, configured by data

GroupTables
Peopleworkspaces, members, projects, shares
Boardtracks, goals, tasks, task_events
Memoryitems, types, links, episodes, embeddings
Agentsagents, activations, events, usage

People never create tables. They choose types, Workers, views and retention, all stored as rows.

4 · Ontology

A small shared vocabulary that domain packs extend

Every brain shares the core types. A project adds a domain pack, and the Curator proposes new types it sees repeat. Nobody has to pick a type to capture something.

5 · An item

Every write carries its own metadata

Agents browse the brain as a folder of md files over MCP. The frontmatter is the row's columns; the body is markdown. Editing the file sends a versioned write, and a stale edit is refused instead of merged.

6 · Search

Word search and meaning search, fused into one score

Both searches run in one SQL query. Reciprocal Rank Fusion combines their rankings, then links and a rerank refine the result.

score(item) = 1 / (60 + word_rank) + 1 / (60 + vector_rank)

Worked example for the query “where do we store vectors”. Items high in both lists win; ranks are used instead of raw scores, so the two scales never need tuning. Claims rank below approved items in the rerank.

7 · Growth

Compress meaning, not files

Storage stays small: 50k items is about 100 MB of text, and their embeddings (1024 dimensions, half precision) about 100 MB more. The real limits are noise and how much an agent can read at once.

8 · Brain science

What human memory teaches the design

The layout already mirrors the brain: a fast store (Inbox), a small workspace (Board), a slow integrated store (Memory) and a sleep pass. Cognitive psychology sharpens eight parts. Every score here is plain SQL on the server; no LLM needed.

Forgetting is a power law

ACT-R activation replaces decay

How often something is needed again tracks its past use (Anderson & Schooler 1991). Only real uses count: cited, opened, confirmed. Forgetting means ranking low, never deleting.

False memories

Provenance the brain lacks

An origin field (you said it, external source, agent inferred, consolidated), frozen first confidence, and corroboration by independent sources only. Search answers know, partial or don't know.

About 4 chunks

A small context packet per task

Working memory holds 3–5 chunks (Cowan). Each task gets at most 4–5 summaries with drill-down pointers, stored so you can see what the agent “had in mind”.

Selective sleep

A smarter Consolidator

Work a priority queue (future need, surprise, importance). Reload old neighbours when rewriting a summary. Fast-track items that fit a well-linked topic; propose a new type when misfits cluster.

Surprise drives learning

Score novelty at write

Near-duplicates reinforce what exists; surprising items get priority. Goals carry an expected outcome, and the gap at the end becomes a lesson.

Remembering to act

If-then intentions

“When the Cohen case comes up, ask about the bank statements.” Checked every time a context packet is built. Released tasks leave a resume note.

Encoding specificity

Context of capture

Store the project, task and agent each item was captured in, and boost it when that context returns. The Curator adds “why it matters” and 2–3 likely future questions.

Spreading activation

Links with fan damping

Activation spreads along links and weakens through busy hubs, so one popular item can't flood results. Items touched in the last hours get a short boost.

B = ln( Σ tj−0.5 )  ≈  ln(n / 0.5) − 0.5·ln(age)   ·   spread = W · (S − ln fan) · link_confidence
final score = α·RRF + β·activation + γ·importance + δ·context match − penalty(proposed, claim)

Where not to copy the brain

Humans rewrite memories when recalling them, drift toward the gist during sleep, treat repetition as truth, and grow more confident the more they recall. sky-brain never edits a source in place, keeps every summary linked to its sources, counts only independent evidence, and lets importance raise priority but never confidence.

9 · Agents

Stewards keep the brain, Workers do the work

An agent's role is fixed when its token is issued, and the Gatekeeper checks this table on every write. A client cannot simply claim to be a Steward.

Stewards · keep the brain

Built in, run in the background: Curator (types, entities, links), Consolidator (nightly sleep, Digest), Archivist (summaries, archiving), Auditor (conflicts, stale facts). Start with one Steward doing the first two jobs.

Workers · do your work

Defined by each person and pulled from the board: Product Owner, Doer, Reviewer, Researcher, a lawyer's paralegal. They read memory and write to the Inbox and the board.

10 · Sharing

Invite people to a project, not to your whole brain

Sign-in stays invite-only through Perminister. Your personal deep memory stays private unless you share a piece of it into a project.

Viewer

Sees the project's board and shared memory. Their agents can read only.

Editor

Adds goals and notes, claims tasks. Their agents act with the same rights.

Admin

Invites others and approves goals in this project.

12 · Blind spots

Ten things that bite a cloud brain

Hebrew search

Postgres has no Hebrew stemmer. Use the simple config plus trigram matching, and a multilingual embedding model.

Who runs the AI

sky-brain calls no LLM. Stewards and Workers run in the person's own connected model (Claude, Codex) and pull jobs over MCP, so their subscription pays. A scheduled routine runs the nightly Consolidator. Only embeddings need a small server-side model, about $0.02 per million tokens.

Forget vs never-delete

People need a real forget. Lawyers will ask for encryption, perhaps a key per workspace.

Memory poisoning

Stored text is fed to agents later. Quarantine imported and web text and mark it as data, not instructions.

The empty brain

Day one has nothing to recall. Imports from Obsidian, Notion, Drive and chat history are needed early.

Files

PDFs, images and voice notes go to file storage with extracted text. Postgres holds the text, not the files.

No quality measure

Keep a test set of questions with known answers and run it on every search change.

Single server

Nanogres runs on one server: off-site backups and a practised restore. Vercel also limits function run time.

Same entity, many names

“Dana” and “Dana Levi” must merge, and the merge must be undoable.

Changing a type

Pack types need versions so old items still validate after a change.

13 · Build order

Each step in daily use before the next

  1. Schema v2. Types, extended items, links, episodes, events, and Hebrew-aware word search.
  2. MCP memory tools. Capture, search, get and context-for-task, plus a read-only md vault.
  3. One Steward. A nightly job with a budget that writes the Digest page.
  4. Embeddings and RRF. Once pgvector is confirmed and a multilingual model is chosen.
  5. Summaries, archiving and hard forget.
  6. Domain packs and per-project sharing.
  7. Imports. Obsidian and Notion md, Google Drive, chat history.

Not yet: a graph view, a whiteboard, page editing, web clippers, a separate vector or graph database.
