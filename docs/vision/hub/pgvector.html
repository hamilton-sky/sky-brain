pgvector on Nanogres

sky-brain wants vector search next to word search. This is what pgvector needs from the Nanogres VPS, why an app can't turn it on by itself today, and two ways to offer it.

Done, 15 Nov 2026

Zakai enabled pgvector 0.8.1 on the sky_brain database. The vector and halfvec types and HNSW indexes are available, so step 4 of the build plan (hybrid search) is no longer blocked. The steps below stay as a record and for other Nanogres databases.

What already holds, and what blocks it

I checked this against the nanogres repo (vps-api/) and the pgvector source.

Blocks

pgvector isn't a "trusted" extension. Its control file has no trusted = true, so only a superuser can run CREATE EXTENSION vector.

pgvector/vector.control, v0.8.7
Blocks

Nanogres app and query roles are created NOSUPERUSER, and they should stay that way. So sky-brain's migration role can't enable it.

api.py, ensure_organization_query_role
Already fine

No restart is needed. pgvector doesn't use shared_preload_libraries, and PgBouncer in transaction mode works with it unchanged.

pgvector README
Already fine

The PGDG apt repo is already configured by install-vps.sh for PgBouncer, and it ships postgresql-NN-pgvector.

install-vps.sh, lines 34–56
Already fine

Ownership transfer already skips schemas that belong to extensions, and backups dump CREATE EXTENSION along with the data.

Where each piece lives

Steps

0

Check what's there

Run this as the postgres user on the VPS. If vector shows up, skip to step 2.

sudo -u postgres psql -XAt -c "SHOW server_version_num;" \
  -c "SELECT name, default_version, installed_version FROM pg_available_extensions WHERE name IN ('vector','pg_trgm');"
1

Install the package (once per server)

Match the server's major version (the first two digits of server_version_num). Use the same PGDG target that install-vps.sh uses for PgBouncer, because that repo is pinned at low priority.

. /etc/os-release
PG_MAJOR=$(sudo -u postgres psql -XAtc "SHOW server_version_num" | cut -c1-2)
apt-get update
DEBIAN_FRONTEND=noninteractive apt-get install -y -t "${VERSION_CODENAME}-pgdg" "postgresql-${PG_MAJOR}-pgvector"

No restart is needed. To make it permanent for new servers, add the same line to install-vps.sh next to the PgBouncer install.

2

Turn it on for a database

This runs as the superuser, inside the target database. On Nanogres the physical name has the organization prefix.

sudo -u postgres psql -X -d n206f8ae49c96592a9fb5f687_sky_brain \
  -c "CREATE EXTENSION IF NOT EXISTS vector;" \
  -c "CREATE EXTENSION IF NOT EXISTS pg_trgm;"

pg_trgm is trusted, so the database owner could add it alone. sky-brain wants it for Hebrew-friendly word search, so it's included here.

How to offer it to every Nanogres user:

An "Extensions" actionA dashboard button, plus an API route gated by nanogres:database:manage. It runs run_sql("CREATE EXTENSION …", database=physical_name) for names on an allowlist, such as vector and pg_trgm.Recommended: users stay non-superuser.
Enable on every new databaseAdd the extension in prepare_organization_database. It's simple, but every database pays for it, used or not.
Mark it trustedEdit the control file or add pgextwlist. This is fragile across package upgrades.Not recommended.
3

Smoke test

Run this as the database's normal query role, not the superuser.

CREATE TEMP TABLE t (id int, e halfvec(3));
INSERT INTO t VALUES (1,'[1,0,0]'), (2,'[0,1,0]');
SELECT id, e <=> '[0.9,0.1,0]' AS cosine_distance FROM t ORDER BY 2 LIMIT 1;   -- expect id 1
4

Things to keep in mind afterwards

  • Upgrades: after the apt package updates, run ALTER EXTENSION vector UPDATE; in each database that uses it.
  • Transfers: imports restore as the superuser, so they work. Exports need the other provider to have pgvector too. Neon, Supabase and RDS do.
  • Disk quota: 1024 dimensions in halfvec take about 2 KB a row, plus the HNSW index. 50k items come to roughly 100–200 MB, which counts toward the database quota.
  • Index builds: HNSW builds go much faster with a higher maintenance_work_mem for that session. The default is fine at sky-brain's size.

What sky-brain does once it's on

Step 4 of the sky-brain build plan adds one migration through the migration port. It creates an embeddings table with a halfvec(1024) column and an HNSW cosine index. The migration starts with CREATE EXTENSION IF NOT EXISTS vector, which is a no-op once you've enabled it. Search then fuses the nearest vectors with word search using RRF. sky-brain doesn't need anything else from Nanogres for this.
